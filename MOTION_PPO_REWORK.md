# MediaPipe reference motion and Isaac Lab PPO swimming (v42)

Pointer reversals previously aligned the entire skeleton through its hips and could add a full 360-degree pirouette or flip. The game now loads a real learned joint actor and uses continuous motion phase, slower travel on reversals, bounded pelvis heading, relative chest/neck motion, and articulated gather/reach/dive poses. Automatic steering spins are disabled for the new controller. Explicit combat moves retain their own animation.

The exact user-provided video, https://www.youtube.com/watch?v=nZ3lfpCGimw (Amberofthesea, “Taking a leap in to Dean's Blue Hole”), was downloaded locally for analysis. MediaPipe 1.1.1 processed 792 frames at 30 fps, detecting a person in 790; 743 passed the frame quality gate. Inverted frames were also detected after rotating the analysis image. Occluded landmarks were interpolated and confidence-weighted. The original video is not packaged with the website. Four root-relative clips were retargeted to the existing 19-bone game rig, with bounded angles/rates and blended loop seams.

Actual training ran in Isaac Lab / PhysX on Spark's NVIDIA GB10: 256 parallel 19-link, 54-DOF capsule proxies, 120 Hz physics and 30 Hz control. The trainer implements clipped PPO, GAE, Gaussian exploration and actor/critic updates. Initial PPO-only training was rejected after independent tracking regressed. Actuator-lag calibration and a velocity feedforward warm start were followed by PPO fine-tuning with a reference prior. A final tracking-focused run selected its best independent evaluation checkpoint. Checkpoints, logs, the USD proxy and reproducible scripts are retained in `../motion-training-v42/`.

The final selected actor's independent proxy joint RMSE is approximately 0.0740 rad, compared with 0.0863 for zero residual control (about 14.3% lower). Evaluation changes direction commands and initial phases using seed 9421; it shares the source clips and does not establish generalization to new people/videos. The warm-start-only actor scored 0.0727 rad, so PPO did not improve that particular pose metric further. The complete selected pipeline is reported separately from the analytical feedforward controller and the rejected run.

The browser loads the actor weights in `assets/policy/swim-ppo-v42.json` and the exact reference hash it was trained against, runs the same tanh MLP at 30 Hz, and drives bounded joint springs. Model export parity is checked against PyTorch. Clip selection, pelvis heading and the existing collision-aware travel motor remain explicit game controllers; PPO controls residual joint targets. Arm target IK provides a body-clearance safety constraint. Runtime thigh spread and knee roll are bounded because monocular depth and lower-leg rotation are ambiguous; these bounds are applied before joint springs, rather than snapping rendered bones. Clothing uses a fixed-topology cage fitted to posed torso/leg sections, with the existing compact sleep garment and damage/repair behavior.

Water forces during training approximate neutral buoyancy and per-link drag. A bounded angular stabilization controller assists direction. This is not full fluid CFD or an unassisted muscle-level swimming policy, and the browser does not run PhysX. No Blender training is claimed. Original detailed character/face/hair assets remain the renderer's source.

Verification artifacts and final release hashes accompany the installed build. Training details: `assets/policy/swim-ppo-training-v42.json`. Model extraction provenance: `assets/policy/mediapipe-extraction-v42.json`.
